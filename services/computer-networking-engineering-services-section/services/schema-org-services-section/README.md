# schema-org-services-section

What a page tells search engines and link unfurlers about itself, from the same settled knowledge as
the page, so the structured data cannot drift from the content.

- `article` (and its subtypes), `person`, `organization`, `webSite` (with the SearchAction),
  `webPage`, `breadcrumbList`, `imageObject`, `graph`, `ldScript` -- schema.org as JSON-LD 1.1. A value
  schema.org would not accept (a relative URL, a date that is not ISO 8601, a day that does not exist)
  is an error, not a silent non-result. `ldScript` escapes `<`, `>`, `&`, U+2028 and U+2029, so the JSON
  can never close its own script element and still parses to the same JSON.
- `openGraphTags`, `twitterTags`, `socialMetaTags` -- Open Graph (the four required properties plus
  `article:*`) and Twitter Cards (`summary_large_image` when there is an image); attribute-escaped once.
- `validateSchemaNode(node)` -- holds any JSON-LD node to the published schema.org vocabulary
  (`data/schema-vocabulary.json`, regenerated by `npm run build:vocabulary` from
  `schemaorg-current-https.jsonld`): a known type, properties that apply to it, nested types within the
  property's range, literals of the right form. The builders' own output is tested against it.
- `articleFromFiniteAlgebra`, `articleFromSelectedCells`, `headFromFiniteAlgebra`, ... -- the lift from
  settled `(predicate, object)` cells. Two declared tables name the correspondence; unnamed predicates
  are skipped, never guessed; only affirmed cells are emitted (a denial is the absence of a claim, a
  contradiction is unsettled). A settled algebra and chosen cells give byte-identical markup.
- `extractJsonLd`, `extractSocialMeta` -- read the same data back out of a page with a real HTML parser.

Carries the legacy `web-schema-org` capability.
