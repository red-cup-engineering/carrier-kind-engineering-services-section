# Computer networking engineering services section

Owns reusable protocols and networking topologies that communicate computer
data between systems. Application-layer protocols remain here when their
defining responsibility is interoperable exchange; Web application and server
composition remain under Web Services.

MCP engineering owns its paired HTTP client and server boundary apps; the
server owns incoming HTTP policy while the client owns outbound observation.

## Services

- `http-services-section` and `websocket-services-section` — HTTP/HTTPS and
  WebSocket coding, negotiation, authentication, and message semantics.
- `a2a-services-section` and `mcp-engineering-services-section` — agent
  communication and tool-interface protocol applications.
- `activitypub-services-section`, `micropub-service`, and
  `webmention-service` — federated publication and IndieWeb exchange.
- `oauth-services-section`, `object-capability-services-section`, and
  `ucan-services-section` — authorization and delegated-capability protocols.
- `web-mesh-services-section` — peer-to-peer discovery, transport, and mesh
  topology.
- `x402-services-section` — HTTP payment protocol services.

- `federated-capability-offer-discovery-cell` — source-owned, bounded
  ActivityPub++ SEN/x402 seller-discovery consumer. Its exact source is mounted
  from Red Cup's independent `2026-08-06-federated-capability-offer-discovery-cell`
  repository; AOE/FeltOS/MetroPlat runtime admission and legitimate Work authority
  are separate from the presence of the source. The original source and the
  shared ActivityPub `sen-outbox-client` remain the executable owners; no
  second provider registry or purchase journal is formed here.
