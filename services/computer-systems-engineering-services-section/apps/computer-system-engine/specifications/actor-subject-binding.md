# Receiver-owned actor subject binding

Native actor transport retains its existing authenticated requester. A trusted host may supply a bounded metroplat.subject-binding statement in signed A2A metadata; untrusted operation JSON cannot create this field. A receiving owner must explicitly recognize the exact signer, audience, logical root, call, original account and session before selecting another executor. No default binding or foreign actor impersonation is inferred. Existing operation capability, office and rule authorization remains in force.

The recognized result binds subjectBinding and hand, retains requester and executor separately, and requires native once-only request state and a synchronous exact reply projector. It cannot carry payment. Before effects, current owner authorization runs and the process-lifetime coordination lease must be held. Under that lease, the addressed request is re-read and its executing transition is durably appended. A competing process observes the original request; it never appends a competing obstruction over another process's started or terminal state. Duplicate payload/binding substitutions refuse. An executing request without a terminal record is indeterminate, never automatically re-executed. A terminal duplicate returns its original held outcome.

The sender calls its trusted onRetained observer immediately after obtaining the original request identity and before further asynchronous reads or sender checks. Delivery follows a final admission check. Timeout before any native admission prevents later retention/send. Once native retention may have started, absence of a returned handle is indeterminate rather than proof of no effect. A retained handle is observed without resending. If delivery is uncertain, the error carries that original submission. These guarantees do not make newly issued requests with a different nonce equivalent to an earlier act; callers must not turn an uncertain outcome into a fresh invocation.

## Exact bound state and interrupted admission

CSE-STATE-1: The bound reader accepts one open exact frontier and a complete native transition chain. Legal traces are executing(1), executing(1) followed by processed(2) or obstructed(2), and a pre-effect obstructed(1). Every transition preserves requester, executor, hand, subject binding, exact request material, packet digest and service metadata. A terminal transition contains a safe nonnegative status code and complete output text, byte counts and SHA-256 digests; processed means code zero and obstructed means nonzero. Malformed states, missing predecessors, forks, gaps and post-terminal transitions refuse observation without re-execution. Historical unbound requests retain their existing reader.

CSE-RETENTION-1: prepare returns the request content identity before asynchronous retention. send receives that prepared identity, rejects a changed discovered actor or changed request material before retention, and supplies expectedRequestNi to native custody. recover reads only that identity's existing request head, validates the original actor/audience and subject-binding identity, and returns the original submission. If retention may be underway, the caller keeps this recoverable identity even when no submission was returned. Recovery and result observation never deliver.

CSE-DENIAL-1: An exact dispatcher admission, input-domain, resolution or authorization refusal can become obstructed(1) before work execution. The receiver must acquire the same execution process lease and reread the bound state first. A repeat returns this terminal refusal even when current permission would allow a new act. A missing execution lease or uncertain failure has no fabricated terminal record and remains indeterminate. A lease loser never overwrites a started or completed winner.

## Monotone received outcome, unreleased bound protocol

CSE-OUTCOME-1: A subject-bound `metroplat.dispatch.result` body has exactly `request`, `requestNi` and `result`. `request` is the original envelope address. `requestNi` is the existing ActivityPub reusable-request identity computed from the signature-admitted original wire, not a caller's assertion. The receiver carries it through synchronous native reply preflight. Ordinary unbound envelopes retain their exact old `{request,result}` representation. The sender's bound submission also retains `requestNi`. These changes are one unreleased protocol migration; old proposal handles and responses are refused rather than treated as recoverable current evidence.

CSE-OUTCOME-2: Before a received outcome may change its CSE head, the entrance requires a signature-resolved sender and uses the response's requestNi with native `requestFor` to read the held original request under the exact local actor and remote audience. CSE revalidates this identity, original envelope, content-addressed admission statement, exact verb/operation/input, material digest, CloudEvents source/id and packet digest, original requester/executor/session/hand, and world binding. Missing original custody or wrong material refuses admission and cannot poison an already valid head. The arrived wire remains in native AP/CSE custody.

The result's service.bearer is receiver-derived character recognition, not a caller-selected statement field. The original account, session/hand selector, exact call and world/root stay fixed by the statement and requestMaterial. The receiving owner recognizes that account's existing bearer, checks current harness/hand custody, and rechecks recognition before effects. Outcome admission requires the bearer; cross-result service disagreement is corruption. The entrance does not recreate or independently reread the remote identity root. The unpaid producer may omit operation as a result field; the exact operation remains bound through requestMaterial and statement.call. Obstructions must be an array of strings, and a held executing result has none.

CSE-OUTCOME-3: The native sequence comes only from committed receiver processing witnesses. A duplicate held executing(1) returns that exact executing result, with an optional replay annotation. It does not turn the same sequence into a different indeterminate payload. A lease-loss advisory with no held processing witness is indeterminate and has no sequence. Neither represents a terminal outcome.

CSE-OUTCOME-4: A CSE received-outcome head references existing immutable arrival records, keyed by original request envelope and exact sender/audience. No request or result body is copied. Each normal read follows one head and one arrival address; a conflict follows at most two. The existing store's addressed record/bucket bounds still apply. Each admission has at most four compare-and-swap attempts. Arrival timestamps and receipt order never order processing state. Terminal evidence absorbs earlier nonterminal evidence. Exact duplicates and the replay annotation do not change state. Different payloads at the same committed sequence, or contradictory terminal outcomes, retain two immutable proof addresses and permanently obstruct observation. Later arrivals cannot heal that conflict; all arrivals remain held.

CSE-OUTCOME-5: Every observation revalidates the exact native original request and outcome. A restart cannot downgrade terminal evidence. Observation never resends. Generic ActivityPub replyFor retains its existing latest-arrival semantics; ordinary unbound and payment observation remains unchanged. Bound unpaid outcome custody does not claim support for payment histories.

CSE-OUTCOME-6: Native actor result observation returns one addressed receipt, exactly `{request, recipient, reply, result}`. Bound and ordinary observations use this same contract. The gateway checks its request and recipient against the retained submission and retains the content-addressed reply. Its immediate-result path reads that complete held receipt through the same native observer.
