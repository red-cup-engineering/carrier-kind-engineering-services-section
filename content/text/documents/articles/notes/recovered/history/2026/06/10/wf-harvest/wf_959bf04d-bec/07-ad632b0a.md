## Findings fixed (in `sites/research-library`)

1. **Host-header → 500 on every HTML page (`src/index.ts` `originOf`).** `originOf` built the canonical origin from the raw `Host` header: `http://${ctx.req.headers.host}`. A malformed Host (e.g. `Host: bad host with spaces`) flows into `page()` → `metadataHead()` → `requireMetadata()` → `assertAbsoluteUrl()`, which **throws** on a non-absolute URL, turning every HTML route into a 500. Replaced with `ctx.url.origin`, which web-server already derives through its `safeOrigin()` sanitizer. Verified live: malformed Host now returns `200 OK`.

2. **`/search` JSON parity broke for short queries (`src/index.ts` search handler).** The JSON branch short-circuited a `q < 2` query with a locally-minted `jsonRepr({error:"bad_request", message:"q must be at least 2 characters"})` instead of delegating. The archive's own message is `"q must be at least two characters"` — so the negotiated JSON body diverged byte-for-byte from `/api/search`, contradicting the JSON-parity requirement. Reordered so JSON requests always delegate to `/api/search` and pass the body through verbatim. Verified live: both now return identical archive bodies with `400`.

3. **Dead code (`renderHome` `origin` param + hidden `.canonical-origin` paragraph in `src/render.ts`).** `renderHome` took an `origin` it only emitted into a `hidden` `<p>` that nothing reads (the canonical URL is already carried by `metadataHead`/`<link rel=canonical>`). Removed the parameter, the hidden element, and updated the call site.

## Findings reported (not fixed — out of scope / design judgment)

1. **Prefix-allowlist bypass in the `@561-group/research` dependency (security).** `repoConfinedPath()` in `lib/research/src/archive-api.mjs` checks the allowed-prefix list (`topical-archive`, `lib/taxonomies`, `dev/docs/audits`) against the **un-normalized** decoded string, *then* calls `confinedPath()` which path-normalizes. Final repo-root containment in `confinedPath()` *does* hold (`/etc/passwd` and N-level escapes return 404), so the leak is bounded to the research package directory, not the whole filesystem. This is a bug in the dependency, not the new package — the new package only delegates to it (correctly: it never touches `fs` itself, and `sites/research-library/src/site.test.ts` already asserts the cases that *do* hold). Fix belongs in `repoConfinedPath` (run the prefix check against the normalized path, or reject any decoded input containing `..`). Reporting rather than editing a separate package with its own test/contract surface.
