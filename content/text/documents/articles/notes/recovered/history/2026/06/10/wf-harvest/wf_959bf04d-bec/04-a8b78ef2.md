# Design: `sites/research-library` — the 561 Group Research Library web application

## 1. Summary

A new site package `@561-group/research-library` that serves `lib/research` (83k-file topical archive) as a themed, hypertext web application for agents on this machine, while preserving **full capability parity** with the existing JSON archive API.

Strategy in one sentence: **mount `archiveApiApp()` from `@561-group/research` whole (unchanged, giving us its routes *and* its path confinement), and layer an HTML browse/search/file UI on top via `mergeApps`, where every HTML handler obtains data exclusively by in-process delegation to the archive app's own handlers — never by touching the filesystem itself.**

- Listens on `127.0.0.1:18799` by default (ports 18788/18790/18791/18793/18796 are taken; this is a local agent-facing site, so loopback bind).
- All HTML routes also negotiate `application/json` (Accept header), and every original `/api/*` + `/raw/*` route remains reachable verbatim.
- Composes only scout-confirmed packages: `@561-group/web-server`, `@561-group/research`, `@561-group/web-theming`, `@561-group/web-page-metadata`, `@561-group/web-microformats`.
- No markdown→HTML renderer exists in the workspace (scout-verified), so `.md` bodies render as escaped, readable `<pre>` with front-matter/taxonomy metadata surfaced in the page chrome, plus a `/raw/` link.

Non-goals (deliberate): `web-taxonomy` (requires a full 83k-file walk at startup; the archive API has no full-enumeration endpoint), `web-pagination` (the archive API has no offset/cursor — listings cap at 1000 with a `truncated` flag; we surface the flag instead of faking pages), `web-cool-uris` (content negotiation on the HTML routes already provides the HTML/JSON fan-out), writing any markdown renderer.

## 3. `src/archive-client.ts` — in-process delegation (the security keystone)

**Responsibility:** let HTML handlers consume the archive API *through* `archiveApiApp`'s own resources, so the research package's `confinedPath`/`repoConfinedPath`/`topicPath` confinement (unexported, scout-verified) is exercised on every byte served. This module dispatches; it never resolves paths, never imports `node:fs`.

```ts
import type { App, Context, Repr } from "@561-group/web-server";

export type ArchiveResult = { status: number; type: string; body: string };
export type ArchiveClient = {
  /** GET a JSON endpoint of the archive app, in-process. */
  getJson(pathname: string, query?: Readonly<Record<string, string>>): Promise<{ status: number; json: unknown; raw: string }>;
};

export function createArchiveClient(archiveApp: App): ArchiveClient;
```

Implementation contract:

1. Resource matching replicates **only** the two match forms `archiveApiApp` actually uses (scout ground truth): exact-string equality, and `RegExp` with named groups → `params`. First match wins, in array order. No other matching logic.
2. For a call, build `url = new URL(pathname + queryString, "http://archive.internal")`. `pathname` is passed **still URL-encoded** (see §5.3) — the archive handlers decode their own regex captures via their internal `decodePathParam`; the `URL` constructor's dot-segment normalization (`/../` collapse) is an extra safety layer, not relied upon.
3. Synthetic context: `{ url, params, req: { method: "GET", headers: {} }, locals: {} } as unknown as Context`. The archive handlers (scout-verified) read only `ctx.url`, `ctx.params`, and `ctx.req.method` (for HEAD body suppression); we always call as GET.
4. Await the handler; result is the research package's repr literal `{ status?, type?, headers?, body }`. `getJson` asserts `body` is a string (the archive's JSON helper always returns pretty-printed string + `\n`), `JSON.parse`s it, returns `{ status: status ?? 200, json, raw: body }`. Non-string bodies (the `/raw/` stream route) are out of scope for the client — HTML handlers never delegate to `/raw/`; that route is served directly by the mounted archive app.
5. No resource matched → `{ status: 404, json: { error: "not_found" }, raw: ... }` (cannot happen for the fixed endpoint set we call, but defensive).
6. Query values are inserted with `URLSearchParams` (auto-encoding); callers pass a **whitelisted** param record only (§5.4).

Exports: `createArchiveClient`, types `ArchiveClient`, `ArchiveResult`.

### 4.2 `render.ts`

All functions are pure string builders. Exports:

| Export | Signature / responsibility |
|---|---|
| `encodePath(p: string): string` | `p.split("/").map(encodeURIComponent).join("/")` — the **only** way link hrefs embed archive paths. |
| `page(opts: PageOptions): string` | Wraps article HTML via `render(libraryTheme, articleHtml, ctx)` from `web-theming`. Builds `ThemeContext` with `siteName: "561 Group Research Library"`, nav (`Home /`, `Browse /browse`, `Search /search`, `Taxonomies /taxonomies`, `API /api`, with `current` set), `canonical`, and `metadataHead: metadataHead(pageMetadata)` from `web-page-metadata` (`url`, `title`, `description?`, `schemaType: "WebPage"`, `breadcrumbs?`, and `searchUrl: <origin>/search?q={search_term_string}` on the home page so the WebSite node carries a SearchAction). |
| `renderHome(roots: RootsJson, origin: string): string` | Overview prose (read-only archive, 9 closed UDC roots, agent guidance: "prefer `/api` for machine use"), search `<form method="get" action="/search">`, `<ul>` of root topics linking `/browse/<slug>` with `present` flag, links to `/api`, `/api/grammar`, `/taxonomies`. |
| `renderListing(topic: TopicDirJson, grammar: GrammarJson, origin: string): string` | Directory page: breadcrumbs (§5.3), entry table (name → link, kind, size, modifiedAt, mediaType). Directory entries whose **name** is one of the five branch roles (`archive`, `bibliography`, `explanations`, `specifications`, `terms`) get a `.role-badge` with `title` attribute set to the role description from `/api/grammar`'s `branchRoles`. Truncation notice when `truncated` (`totalImmediateEntries` shown; no fake pagination — the API caps at 1000 with no cursor). Dirs link `/browse/<path>`, files link `/file/topical-archive/<path>` (listing paths are topical-archive-relative; the file view is repo-relative — conversion happens here, in link construction only). |
| `renderFile(file: FileJson, repoPath: string, origin: string): string` | File page: title = `frontmatter.title ?? name`; metadata `<table class="fm-table">` of all front-matter keys; `taxonomyIds` (udc-id, msc-id, arxiv-id, acm-ccs-id, mesh-id, aat-id, lcc-id) rendered as labelled badges using the field descriptions from `/api/grammar`'s `taxonomyIdFields`; file facts (size, modifiedAt, mediaType, sha256 when present); body: if `sample` present → `<pre class="file-body">` of **escaped** `sample.text` with a truncation notice + "fetch full file" link when `sample.truncated`; if no sample (binary/non-text extension) → "binary or non-text file" notice. Always a prominent link to `` /raw/<encodePath(repoPath)> `` ("raw download, exact bytes") and to the JSON record `` /api/file/<...>?hash=1 ``. Page metadata uses `schemaType: "Article"`, `published`/`modified` only if values parse as valid dates (web-page-metadata is fed sanitized values). No markdown rendering: scout confirmed no renderer exists anywhere in the workspace, and writing one is out of scope — escaped `<pre>` is the specified fallback, and agents read raw markdown fine via `/raw/`. |
| `renderSearchPage(query: SearchQuery, result: SearchJson \| null, origin: string): string` | Search form (inputs: `q`, optional `path` scope, `limit`, `maxScan`) prefilled from the query. When `result` present: results as an **h-feed** via `web-microformats` `hFeed({ title, url, entries })` where each entry = `{ id: path, url: absolute /file/ or /browse/ URL, title: path, summary: "<kind> · <size> bytes · <modifiedAt>" }` (absolute URLs built from `origin` — microformat entry URLs are kept absolute to match the rest of the web-* stack's validation posture). Below the feed: `scanned`, `truncated` ("more results exist; raise limit"), and `scanTruncated` ("only N of ~83k entries scanned — add a `path` scope or raise `maxScan`, max 100000") notices. The `scanTruncated` warning is essential: default `maxScan=10000` covers ~12% of the tree. |
| `renderTaxonomies(listing: TaxonomiesJson, origin: string): string` | Lists the `lib/taxonomies` `.ttl` files, each linking `/file/lib/taxonomies/<name>` and `/raw/lib/taxonomies/<name>`. |
| `renderError(status: number, message: string, origin: string): string` | Themed error page used when a delegated call returns ≥400 in an HTML branch. |
| `breadcrumbs(repoOrTopicPath, kind): string` | `<nav class="crumbs">`: `Library / <root> / ... / <leaf>`; segments under `topical-archive/` link to `/browse/<encoded prefix>`; segments under `lib/taxonomies` or `dev/docs/audits` are plain text except files (no directory listing exists for those prefixes via the API). Also feeds `PageMetadata.breadcrumbs` for the JSON-LD BreadcrumbList. |

Escaping: `render.ts` uses `escapeHtml`/`escapeAttr` re-exported from `@561-group/web-theming` (scout-confirmed exports) for **every** interpolated value — entry names, paths, front-matter keys *and* values, sample text, query echo, error messages. No value sourced from the archive or from the request ever reaches HTML unescaped; no `innerHTML`-style passthrough exists.

`origin` is derived per-request: `originOf(ctx) = "http://" + (ctx.req.headers.host ?? \`127.0.0.1:${DEFAULT_PORT}\`)` (exported from `render.ts`), used for canonical URLs, JSON-LD, and h-feed absolute URLs.

## 5. `src/index.ts` — composition root and routes

### 5.1 Factory

```ts
import { createRequire } from "node:module";
import path from "node:path";
import { mergeApps, htmlRepr, jsonRepr, textRepr, type App, type Context } from "@561-group/web-server";
import { archiveApiApp, ROOT_SLUGS } from "@561-group/research";
import { createArchiveClient } from "./archive-client.ts";

export type ResearchLibraryOptions = { root?: string };
export const DEFAULT_PORT = 18799;
export { ROOT_SLUGS };

export function defaultResearchRoot(): string {
  // robust under pnpm isolation; no hardcoded machine path
  const require = createRequire(import.meta.url);
  return path.dirname(require.resolve("@561-group/research/package.json"));
}

export function createResearchLibraryApp(options: ResearchLibraryOptions = {}): App;
```

Inside `createResearchLibraryApp`:

1. `root = options.root ?? defaultResearchRoot()` → resolves to `lib/research` (the dir containing `topical-archive/`, `lib/taxonomies/`, `dev/docs/audits/`). **Never** `process.cwd()` (scout caveat #1).
2. `const archive = archiveApiApp({ root });` `const client = createArchiveClient(archive);`
3. Grammar memo: `let grammarPromise; const getGrammar = () => grammarPromise ??= client.getJson("/api/grammar").then(r => r.json);` — `BRANCH_ROLES`/`TAXONOMY_ID_FIELDS` aren't exported, so the grammar endpoint is the sanctioned source, fetched once, lazily.
4. `const htmlApp: App = { problems: true, security: { contentTypeOptions: "nosniff", frameOptions: "DENY", referrerPolicy: "no-referrer" }, resources: [ ...html routes... ] };`
   - Security object mirrors the archive API's exactly. We do **not** use `security: true`: its strict CSP (`default-src 'self'`) would block `web-theming`'s inline `<style>` in browsers. `mergeApps` first-defined-wins makes this object the app-wide policy.
   - **No app-level `cacheControl`** (scout caveat: it shadows every per-Repr value). Per-Repr instead: HTML pages `{ visibility: "public", maxAge: 60 }`, `/healthz` `{ noStore: true }`.
5. `return mergeApps(htmlApp, archive);` — htmlApp first, so our `/` (exact-string match) shadows the archive's minimal `/` index; **everything else in the archive app dispatches untouched** (its `/api/*` matchers don't collide with ours).

### 5.2 Route table (complete)

All routes `methods: ["GET"]` (HEAD auto-admitted, OPTIONS auto-204 — pipeline behavior). Every templated/regex route sets `route:` for observability and `id:`.

**HTML layer (defined in this package; first in merge order):**

| id | match | route | produces | handler behavior |
|---|---|---|---|---|
| `home` | `"/"` (exact) | `/` | `["text/html","application/json"]` | Delegate `client.getJson("/api/roots")`. JSON branch (`ctx.negotiatedType === "application/json"`): return `{ kind: "library.home", service: "@561-group/research-library", roots: <roots json>, endpoints: { api: "/api", browse: "/browse/<topic-path>", file: "/file/<repo-path>", search: "/search?q=", raw: "/raw/<repo-path>" } }` via `jsonRepr`. HTML branch: `htmlRepr(renderHome(...))`. No Accept header → HTML (first listed). |
| `browse` | `/^\/browse(?:\/(?<topic>.*))?$/` | `/browse/:topic*` | `["text/html","application/json"]` | `raw = ctx.params.topic ?? ""` — **kept encoded** (regex captures are not decoded; see §5.3). Delegate `client.getJson("/api/topic/" + raw, passthrough(ctx, ["limit","counts","hash","sample","bytes"]))` with `counts` defaulted to `"1"`. JSON branch: return delegated raw body + status verbatim (`{ status, type: "application/json; charset=utf-8", body: raw }` — exact parity with the API shape). HTML branch: status ≥400 → `renderError`; `kind === "archive.topic"` directory → `renderListing` (with `await getGrammar()`); file kind → re-delegate once with `sample=1&bytes=65536` and render via `renderFile` (browse landing on a file shows the file view; canonical link on that page points at `/file/topical-archive/<path>`). |
| `file` | `/^\/file\/(?<file>.+)$/` | `/file/:repo-path*` | `["text/html","application/json"]` | `raw = ctx.params.file` (encoded). Delegate `client.getJson("/api/file/" + raw, { sample: "1", bytes: clampTo200000(ctx.url.searchParams.get("bytes") ?? "65536"), ...passthrough(ctx, ["hash"]) })`. Confinement (3-prefix whitelist + traversal rejection) is enforced inside the archive handler; a `/file/../../etc/passwd` request yields the archive's 400, rendered as a themed error page (HTML) or passed through (JSON). JSON branch: verbatim passthrough. HTML branch: `renderFile`. |
| `search` | `"/search"` (exact) | `/search` | `["text/html","application/json"]` | `q = (ctx.url.searchParams.get("q") ?? "").trim()`. If `q.length < 2`: HTML → form page with hint (status 200, no delegation); JSON → `jsonRepr({ error: "bad_request", message: "q must be at least 2 characters" }, 400)`. Else delegate `client.getJson("/api/search", passthrough(ctx, ["q","limit","maxScan","path","roots"]))`. JSON: verbatim passthrough. HTML: `renderSearchPage` (h-feed results + scan/truncation notices). |
| `taxonomies-page` | `"/taxonomies"` (exact) | `/taxonomies` | `["text/html","application/json"]` | Delegate `/api/taxonomies`; JSON passthrough; HTML `renderTaxonomies`. (Does not collide with the archive's `/api/taxonomies`.) |
| `healthz` | `"/healthz"` (exact) | `/healthz` | `["text/plain"]` | `textRepr("ok\n", { status: 200, cacheControl: { noStore: true } })`. Effective because no app-level cacheControl exists. |

**Inherited verbatim from `archiveApiApp` (capability parity — not reimplemented):**

| route | capability |
|---|---|
| `/api` | manifest JSON |
| `/api/grammar` | path grammar, branch roles, taxonomy id fields |
| `/api/roots` | 9 closed root topics + presence |
| `/api/topics?path=&limit=&counts=1` | confined directory listing |
| `/api/topic/<topic-path>?limit&counts&hash=1&sample=1&bytes=` | topic dir/file records, frontmatter+taxonomyIds, samples |
| `/api/search?q=&limit=&maxScan=&path=\|roots=` | path-substring search with limits/scan caps |
| `/api/file/<repo-path>?hash=1&sample=1&bytes=` | repo-relative records incl. **sha-256 hash route** (`?hash=1`) |
| `/api/taxonomies` | taxonomies dir listing |
| `/raw/<repo-path>` | confined raw file streaming, correct content-type, text **and binary** (PDFs etc.) |

The archive app's own `/` HTML index is the only shadowed resource (ours is richer and links `/api` anyway).

### 5.3 Path-encoding discipline

- Our `/browse` and `/file` regex captures are **not** URL-decoded (web-server decodes only `:segment` string-template params). We pass captures, still encoded, straight into the delegated archive pathname; the archive's own regex + `decodePathParam` performs the single, authoritative decode, then confinement. Exactly one decode happens, and it happens inside the research package. Malformed percent-encoding → archive returns 404/400, which we surface.
- Outbound links always go through `encodePath()`.

### 5.4 Query passthrough discipline

`passthrough(ctx, allowed: string[])` (private helper in `index.ts`) copies only whitelisted params from `ctx.url.searchParams` into the delegated query record, as strings. User query input therefore only ever becomes URL search params consumed by the archive API's own validators (limit/maxScan clamping, scope confinement, q-length checks) — never a filesystem path, never an unescaped HTML fragment.

## 7. Security review checklist (design-level)

1. **Path confinement is reused, not reimplemented.** The only code that maps request input to filesystem paths is inside `archiveApiApp` (`confinedPath`/`repoConfinedPath`/`topicPath`, unexported). This package imports `node:fs` nowhere; `archive-client.ts` dispatches to archive handlers, `render.ts` builds strings, `index.ts` composes. A grep for `node:fs`/`readFile`/`createReadStream` in `sites/research-library/src` must return nothing — add that as a review gate.
2. **Escaping:** every interpolation in `render.ts` goes through `escapeHtml`/`escapeAttr` (web-theming); hrefs through `encodePath` + `escapeAttr`. Sample text (arbitrary archive content) is escaped inside `<pre>`.
3. **Read-only:** all routes GET/HEAD; no body readers imported; method mismatch → pipeline 405.
4. **Headers:** `nosniff`, `DENY` framing, `no-referrer` app-wide (matching the archive API); `problems: true` for structured errors on the HTML app, archive keeps its own `{error,message}` JSON shapes.
5. **No external npm deps**; workspace packages + `node:module`/`node:path`/`node:url` builtins only.
6. Single-decode rule (§5.3) prevents double-decode traversal tricks; the archive's confinement rejects `..` segments and absolute paths after its decode regardless.

## 8. Test plan (`node --test`, per workspace convention)

Scout finding: no request-injection/mock helper exists; the codebase idiom is `start(app, { host: "127.0.0.1", port: 0 })` + global `fetch` + `finally running.close()`. We use that for integration tests, and pure in-process calls for unit tests. Tests run against the **real archive** at `defaultResearchRoot()` but select fixtures **dynamically** (query `/api/roots`, pick the first `present` root, list it, walk to the first file) so they don't break as the 83k-file tree evolves.

### `src/archive-client.test.ts` (no network)

  - `getJson("/api/roots")` → status 200, `json.kind === "archive.topical-roots"`, `json.count === 9`, slugs equal `ROOT_SLUGS`.
  - `getJson("/api/grammar")` → has `branchRoles.terms` and 7 `taxonomyIdFields`.
  - `getJson("/api/topic/" + firstPresentRoot)` → `kind === "archive.topic"`, entries array.
  - Confinement passthrough: `getJson("/api/file/%2e%2e%2f%2e%2e%2fetc/passwd")` → status 400; `getJson("/api/file/etc/passwd")` (disallowed prefix) → 400.
  - Unknown path → 404 shape.

### `src/render.test.ts` (pure functions)
- `encodePath("a b/c#d")` round-trips segment-wise; no raw `/`-injection.
- `renderFile` with a synthetic file record containing `<script>` in name, front-matter value, and sample text → output contains `&lt;script&gt;`, never `<script>`.
- `renderListing` marks an entry named `bibliography` with `role-badge` and the grammar description; sets `truncated` notice when flagged.

- `page()` output starts with `<!DOCTYPE html` and contains the `metadataHead` JSON-LD `<script type="application/ld+json">` (web-theming `render` contract: wrap must include article verbatim — implicitly verified by it not throwing).
